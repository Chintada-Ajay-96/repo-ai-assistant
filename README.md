# Repository AI Assistant

A lightweight, reliable repository analysis, code chunking, and embedding generation engine inspired by Cursor/Copilot-style systems. It indexes source code using WebAssembly-based Tree-sitter grammars, produces semantic code chunks, and generates high-dimensional embedding vectors for code retrieval.

---

## Architecture Pipeline

```text
Phase 1:
Repository → AST → Symbols
       │
       ▼
Phase 2A:
Symbols → Code Chunks
       │
       ▼
Phase 2B:
Code Chunks → Embeddings
```

```
Repository Root
       │
       ▼
src/utils/walkRepo.ts  ──► Recursive directory discovery
       │                   (Filters node_modules, .git, dist, build)
       │                   (Detects language from extension)
       ▼
src/repoMap.ts         ──► Tree-sitter WASM loading & parser caching
       │                   (JavaScript, TypeScript, and TSX grammars)
       ▼
AST Traversal          ──► Recursive syntax tree traversal & symbol extraction
       │                   (Preserves hierarchy, parent classes, line numbers)
       ▼
Repository Map         ──► Structured symbol list per file
       │
       ▼
src/codeChunks.ts      ──► Exact line extraction & chunk creation
       │                   (Extracts source code lines, deduplicates, preserves context)
       ▼
Code Chunks            ──► Meaningful, retrieval-ready code chunks
       │
       ▼
src/embeddings.ts      ──► Metadata-enriched input formatting & API batching
       │                   (Model: text-embedding-3-small, 1536 dimensions)
       ▼
Embedded Code Chunks   ──► Chunks paired with high-dimensional vector representations
```

## Phase 2B: Embedding Generation

### What is an Embedding?
An **embedding** is a vector (a list of numbers, e.g., 1,536 floats) generated by an AI model that captures the semantic meaning of a text or code snippet. Pieces of code that do similar things (e.g., verifying passwords vs validating credentials) end up close to each other in multi-dimensional vector space, even if they use completely different variable names.

### Why Embed Code Chunks?
- **Semantic Code Search**: Keyword search only finds exact string matches. Embedding vectors allow an assistant to find code based on what it *does* (e.g., searching "JWT token signing" will match `generateToken` even if the word "JWT" isn't in the function name).
- **Metadata Context**: We embed not just raw code, but structured metadata (`Language`, `File`, `Symbol`, `Type`, and `Parent`), ensuring the embedding model understands class ownership and file location.
- **Future Retrieval (RAG)**: In upcoming phases (2C/2D), these vectors will be stored and queried so that a coding assistant can retrieve the exact relevant functions for user questions.

> **Note:** Vector databases, persistent vector storage, and similarity search are **not** part of Phase 2B and will be implemented in subsequent phases.

## Data Structures

### CodeChunk (Phase 2A)
```ts
export interface CodeChunk {
  file: string;
  language: string;
  symbol: string;
  type: string;
  startLine: number;
  endLine: number;
  code: string;
  parent?: string;
}
```

### EmbeddedCodeChunk (Phase 2B)
```ts
export interface EmbeddedCodeChunk {
  chunk: CodeChunk;
  embedding: number[]; // 1536-dimensional vector (text-embedding-3-small)
}
```

### Formatted Embedding Input
Each chunk is formatted before embedding to include semantic metadata:
```text
Language: javascript
File: sample-repo/auth.js
Symbol: verifyToken
Type: function

Code:
function verifyToken(token) {
    return jwt.verify(token, SECRET);
}
```

## Environment Configuration

An OpenAI API key is required **only** when generating live embeddings (the automated test suite uses mocks and runs without any API key or network access).

1. Copy `.env.example` to `.env` or set the environment variable directly:
   ```bash
   # Windows PowerShell
   $env:OPENAI_API_KEY = "your-api-key-here"

   # Linux / macOS / Bash
   export OPENAI_API_KEY="your-api-key-here"
   ```
2. Never commit `.env` or hard-code keys in files. `.env` is listed in `.gitignore`.

## Scripts & Usage

### 1. View Code Chunks (Phase 2A)
Analyze the default sample repository and view the extracted code chunks:
```bash
npm start
```

### 2. Run Embedding Demonstration (Phase 2B)
Generate embeddings for the sample repository:
```bash
npm run embed
```
*(If `OPENAI_API_KEY` is not set, a helpful guide is displayed without crashing).*

### 3. Run Automated Tests
Run all unit and integration tests (zero network calls, zero API key required):
```bash
npm test
```

### 4. Type Check
```bash
npx tsc --noEmit
```
